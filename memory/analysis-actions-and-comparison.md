# 명칭 확인·분석 조치·선택 비교 (2026-10-13)

- 사용자가 추천 1·2·3 전체 구현을 승인했다. 수집은 계속 요청 시만 실행한다. 이번에는 기존 캐시 원본을 재해석했으며 새 원본을 수집하지 않았다.
- 원본 `ops.json`의 엔티티 키와 금액은 보존한다. 원본 이름, Cost Center, 실적 행/필드/원가 항목의 입력 여부를 필드 추가로 저장한다. 원본 수집 시에도 같은 메타데이터를 생성한다.
- `entityIdentity.js`: 사용자가 확인한 Hai Nam (북부)와 HAINAM만 분석 뷰에서 연결. 북부, 창고 3120083019, 운송 3120083015 확인 필수. 새 Cost Center·다른 지역·다른 사업은 연결 거부. 창고/운송 세그먼트는 그대로 분리한다. 미지정 과거 실적은 북부로 옮기지 않는다.
- 다른 이름은 같은 지역·사업의 Cost Center가 이어질 때 ‘명칭·배부 변경 후보’만 표시한다. 실제 물리 위치는 미확인이다. 고객사는 같은 Cost Center만으로 이름을 연결하거나 후보로 추정하지 않는다.
- 입력 0, 원본 칸 미입력, 대상 실적 행 없음, 전체 미집계 월을 구분한다. 확정 기간 내 기존 엔티티의 명시적 전체 0 행도 입력으로 기록하며 미래 0 템플릿은 제외한다. 금액이 전부 0인 신규 엔티티는 기존 수집 대상 범위에 추가하지 않는다.
- `DecisionLinkProvider`는 기존 이메일 허용 정책 및 uid별 decisionBoards를 사용한다. 분석/수익성/명칭 후보의 조치 등록과 경영실적 TOP 5/상세 점검을 의사결정 작성본으로 전달한다. Google 로그인 전에는 세션 내 분석을 보관하고 로그인 후 계속한다.
- 같은 원본·대상·항목·필터·기간·사유는 SHA-256 기반 같은 문서 ID를 사용한다. 기존 이슈를 재개하고 완료/진행 상태를 분석 화면에 표시한다. 트랜잭션 revision 비교·history 동시 저장을 유지하며 다른 기기 수정을 덮어쓰지 않는다. 분석 수치·출처는 등록 시점의 스냅샷으로 보존하고 의견·대안을 생성하지 않는다.
- 작성본은 uid별 여러 이슈로 임시 보관·복원 가능. 사용자 변경 시 편집 화면을 다시 마운트하여 개인 작성본이 다른 사용자에게 넘어가지 않게 한다.
- 고객사/창고 목록에서 최대 5개 체크 → 선택 비교표. 매출·매출이익·영업이익·영업이익률·월평균 매출·전기→당기·매출 증감/증감률·이익 증감 기여·입력/판정 표시. 두 카테고리 모두 조회 월 선택 지원.
- 월평균은 해당 지표 입력 월 합계/입력 개월(입력 0 포함, 미입력/행 없음 제외). 증감은 전기/당기 동일기간 입력이 완전한 경우만 표시한다. 기여도는 선택 대상의 영업이익 증감 절댓값 합계 기준. 2023/24 지역 누락 주의 유지.
- 검증: 모든 연도·월 6개 손익 지표 및 모든 원가 항목 합계 유지, 다른 지역/사업/Cost Center 연결 거부, 입력 상태·동일기간 계산·중복 ID·사실 기반 작성본 테스트. 실제 Google 계정으로 클라우드 저장/상태 왕복은 사용자 로그인 후 검증 필요. 보안 규칙과 OAuth 권한은 바꾸지 않았다.
